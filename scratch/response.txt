Investigate progressively faster PyTorch-native alternatives.

4. Risks

Primary Risks

The sequential recurrence is algorithmically sequential; Python optimization alone may not eliminate the dependency chain.

torch.compile() may not fuse the scan effectively on the Kaggle environment.

Replacing the scan with an approximation changes the underlying model, requiring fair scientific comparison.

Reducing state size or depth may improve speed but reduce representational capacity.

Vectorized approximations may introduce numerical differences from the intended recurrence.

Scientific Risks

Runtime improvements should not alter preprocessing, evaluation protocol, or subject splits, to preserve comparability with previous phases.

Any architectural replacement (e.g., GRU instead of Mamba) should be treated as a distinct experimental condition rather than an implementation optimization.

Optimization should preserve the validated training pipeline so that observed AUROC differences can be attributed to the sequence model rather than unrelated implementation changes.
